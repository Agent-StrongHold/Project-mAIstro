# A2A Warden ingress (#1137)

Nine new collected cases exercise the two shipped delegation ingress paths:
in-process payloads scan nested values and attacker-controlled mapping keys
before task admission; cross-instance peer responses scan the complete
serialized response before a transport receipt is accepted. Additional cases
cover explicit Warden unavailability, denied resumed results, and audit
correlation for the parent Run, receipt, Workspace/Project scope, and trace.

Three of the cases drive the guest-peer ingress over a real TCP socket served
by a peer in a separate OS process (stdlib `http.server`), closing the
MockTransport-only gap a deep review flagged: prompt-injection text in an
ordinary value, a nested structure, and an attacker-controlled key is refused
by the shipped canonical detector, the exact wire representation is what
Warden scans, and a clean peer over the same socket is still delegated to
normally (the refusal is content-driven). A further case pins fail-closed
behavior on the guest-peer response path itself: with the Warden policy
explicitly unavailable, an otherwise-clean peer response is refused rather
than accepted as a trusted transport receipt.
