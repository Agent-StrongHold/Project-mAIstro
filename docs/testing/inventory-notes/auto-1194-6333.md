`test_production_remote_work_kind_is_not_retried_under_a_retry_budget` is one
new test in `packages/maistro-core/tests/graph/durable_runs/
test_attempt_executor.py`. It resolves the shipped `agent.remote_work` kind
through the production registry (`compose_node`, not a test double) and runs a
durable graph whose node policy asks for `max_attempts: 3`. The repair behind
#1194 makes that kind declare `ReplaySemantics.NON_RETRYABLE` — its work
executes at an A2A peer, so whether a failed visit already produced the remote
effect is not locally observable and reconciliation belongs to the delegation
recovery path, never a blind second visit. The test pins that the executor
honours the declaration mechanically: the Run fails with exactly one Attempt
and one visit despite the retry budget, and the catalog declaration itself is
asserted so it cannot regress to the inherited `PURE` default silently.
