## +5 — `capabilities/test_invocation_store.py`, the `claim` exits

`SqliteInvocationStore.claim` is this branch's atomic admission seam, and the
diff-coverage gate measured it at 56% of 25 changed lines. It opens
`BEGIN IMMEDIATE` before reading history, so every exit owes the database a
rollback — and three of its four exits had no test. The untested ones are the
failure paths, which only occur when two workers race, which is exactly when
nobody is watching.

- **a completed prior is returned, not re-dispatched** — and the write lock is
  released to say so. Returning from inside `BEGIN IMMEDIATE` without the
  rollback strands the lock on a connection that has decided to do nothing.
  Asserted by performing an unrelated write afterwards, which would block.
- **a non-terminal prior is refused as an unsafe retry** — `RUNNING` means the
  remote outcome cannot be proven absent.
- **a FAILED prior is admitted** — the one eligible case, because `FAILED` is
  `EffectNotApplied` evidence that nothing was applied.
- **a lost insert race raises `UnsafeEffectRetry`, not `IntegrityError`** — a
  caller that catches the former to re-read canonical history would not catch
  the latter, so the loser of a cross-connection race would crash instead of
  replaying. Provoked with a claim whose in-transaction history read finds
  nothing but whose insert collides: the winner's row is invisible to the
  reader and real to the index.
- **an unexpected escape still releases the write lock** — the bare
  `except BaseException` is load-bearing, not defensive noise. A cancellation
  is not an `Exception`, and one that skipped the rollback would strand the
  lock for the life of the process. Driven with `KeyboardInterrupt`, proved by
  a subsequent write.
