# auto-18-1584 — legacy sandbox launcher retired behind the canonical authority

`tools/sandbox/docker.py` was the last second launcher: it hand-assembled its
own `docker run` argv, re-added capabilities after dropping them, ran the image
default user, and gated egress on a settings boolean. This change rewrites it
as the legacy call-signature facade over `maistro.sandbox` (selector, policy
ladder, egress grants), so the evolve benchmark and RSI's development sandbox
consume the one authority. The gate (`scripts/check-sandbox-authority.py`) now
sees container-run flag vocabulary anywhere under `packages/` and pins the
facade's canonical import.

## packages/maistro-core/tests (−12) and tests/sandbox (+4)

- `tests/tools/sandbox/test_docker.py` (−14): every test pinned the retired
  launcher's private argv (`docker exec` elements, cap/network flags,
  `_safe_path`, the `asyncio.create_subprocess_exec` boundary). Rebased
  to 8 tests that pin the facade translation instead: ladder selection with a
  stub vm-tier backend behind the real `SandboxSelector`, default-deny egress,
  explicit opt-in → audited HOST grant, settings → policy ceilings, fail-closed
  refusal on an empty selector, unauthorized-root refusal, dangerous-command
  block, TTL/context-manager.
- `tests/tools/test_sandbox_paths.py` (+4): six tests pinned
  `SandboxContainer._safe_path`, which no longer exists; containment now lives
  in `maistro.sandbox.paths`. Same properties re-pinned against
  `_relative_parts` (relative resolves under root, absolute outside the mount
  rejected, `..` traversal rejected incl. mid-path, dot-path normalized,
  filename) plus guest-absolute-under-mount acceptance and read/write-beneath
  roundtrip + symlink-refusal semantics.
- `tests/tools/test_workspace.py` (−3): `TestEnsureWorkspace` pinned
  `ensure_workspace`, deleted with the retired launcher (creation is now
  `maistro.sandbox.paths.validate_host_root(create=True)`); the
  `validate_workspace_path` allowlist tests are untouched.
- `tests/sandbox/test_selector.py` (+4): the new `WorkloadPolicy` egress
  consistency check — `network_allowed` contradicting the `EgressGrant` is
  rejected at construction; standard policies assert self-consistent.
