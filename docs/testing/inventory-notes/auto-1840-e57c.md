# 1840-chat-429-capacity-backpressure

Six parameters of `test_chat_capacity_refusal_returns_429_before_model_or_stream`
plus `test_a_turn_is_admitted_again_once_capacity_returns` (#1840, parent #1182).

Conductor conversation chat used to answer a full canonical active-Run ceiling
with the same retryable 503 as any other admission failure, because
`admit_turn` mapped every ordinary exception to `_unavailable`. The new
parameterized test saturates the actual configured `RunStore` ceilings — the
caller's own principal for the principal scope, other principals in the turn's
Workspace (the caller's default Workspace for voice, which selects none) for
the Workspace scope — through the store's own `create_run`, then drives
`/v1/chat/complete`, `/v1/chat/stream`, and `/v1/voice/intent` through the
shipped routes on the real embedded Container. Each variant must answer 429
with the maistro-server detail convention and `Retry-After`, leave the model
gateway un-called, preserve the saturated Runs' identities and lifecycle state,
add no Run/NodeRun/Attempt, and leave no dispatch-pending residue. The recovery
test proves a valid turn is admitted again once the seeded capacity settles.

No existing case was removed or weakened; the prior 503 and cancellation
behavior keeps its coverage.
