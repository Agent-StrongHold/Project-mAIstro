# auto-404 CI repair — Quality-gate ratchet violations, and their upstream resolution

This note records two rounds of work on the auto-404 lane and deliberately
carries **no** `inventory-delta:` block: the net test-count effect of both
rounds on `packages/maistro-core/tests` is zero (see the postscript below).

## Round 1 (commit `ecf7fb5ff`)

The branch's merge-queue evaluation failed the Quality gate on two
develop-inherited ratchet violations that the merge commit `7311afff4`
brought in from `430139cb`: the new `Principal.from_legacy_dict` block at
C(14) (radon) and nine relocated/unbanked vulture identities in the
`maistro.identity` refactor (crypto split into `_crypto.py`, bridges into
`principal.py`). Grants are read from the base revision (ratchet
provenance), so the only in-branch repair is to genuinely clear the
findings.

The radon half refactored `from_legacy_dict` from one C(14) block into two
private helpers (`_frozen_str_set` A(3), `_roles_from_legacy` A(2)) plus the
classmethod itself at A(5). That is a behavior-bearing decomposition of a
cutover adapter, so 16 maistro-core node IDs in
`tests/identity/test_principal_bridge.py` pinned the bridge's parsing
precedence first: `id`/`user_id` fallthrough and precedence, single-`role`
override of a `roles` collection, non-collection roles/scopes rejected,
`workspace_ids`/`workspaces` alias with empty-list fallthrough, `org_id`
str coercion or None, `team_ids` item coercion, and the `to_legacy_dict`
symmetry (minimal payload, full payload, sorted `primary_role`, full
round-trip). All 16 ran green against the pre-refactor implementation and
passed unchanged after it.

The vulture half carried no tests: the nine identities were reviewed
retained public-API surface, banked via documented whitelist references in
`packages/maistro-core/src/_vulture_whitelist.py` (with the same rationale
comments the file already uses), and the ten now-stale ledger rows were
pruned from `quality/vulture-baseline.json` as the gate requires.

## Postscript — upstream revert, adopted by the develop sync (this round)

Before this branch could re-enter the merge queue, `develop` reverted the
entire `430139cb` feature (`28e2a03a8`, #1769): `identity/principal.py` and
`identity/_crypto.py` were deleted and `identity/__init__.py` restored to its
pre-refactor shape. Syncing `origin/develop` (`c91e354f3`) into auto-404
therefore resolves that modify/delete conflict **in favor of the upstream
revert** — the cutover bridge, the 16-test bridge lock
(`tests/identity/test_principal_bridge.py`), and the ADR-068/ADR-021
whitelist references all came out with the feature. The +16 delta above was
superseded by this −16, so the lane's net effect on the maistro-core suite
is zero and this note records no delta.

The vulture-ledger pruning from Round 1 survives the merge only where the
post-merge tree still makes those rows stale; `quality/vulture-baseline.json`
was re-reconciled against the post-merge tree so
`scripts/check-vulture-baseline.py` runs exact (no new findings, no stale
rows).

The next merge-queue evaluation still failed the Quality gate, and the
driver-executed check logs referenced by the lane brief were absent from the

tree (`2f4bfe1a4`, then the `02422a420` sync `a4d717396`). Results: ruff

new base), `mypy --strict` clean on `tools/git/`, targeted suites green (144
passed: `tests/tools/git` + maistro-rsi `test_cli`/`test_selfbranch`).

The vulture half was rebuilt from the real scan rather than the prior
worker's uncommitted hand sketch: `check-vulture-baseline.py --update`
banked all 1484 identities the vulture-2.16 scan of this tree produces and
pruned every stale row, including the six previously-named
`identity/__init__.py` identities, which the post-revert tree no longer
produces (recording them would have been stale debt). Candidate bookkeeping
is now exact: `candidate_added` = `candidate_removed` =
`candidate_unbanked` = 0, `unclassified` = 0, `never_allowlist` = 0.

The gate still exits 1, and the residue is provably upstream: the vulture
finding set of the merge-base tree `c91e354f3` (scanned in a detached temp
