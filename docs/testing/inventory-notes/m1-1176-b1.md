## Repair round 2 (this worktree)

Audit finding `idempotency.py:1236-1248` — *returns `InMemoryTaskIdempotencyStore`
after configured PostgreSQL provisioning failure, violating the
no-process-local-cache stop condition* — was the one live item: the earlier
repair commit (`a2feb6c1`) had already closed the claim-fence and
ambiguous-window findings (`queue.py` begin-before-mint + token fences +
compensation; the death-after-mint / death-before-mint tests), the durable
server E2E had replaced the in-memory-runstore restart simulation with real
SQLite claim files and fresh connections, and the PR-head mismatch is a
GitHub-plumbing observation this worktree cannot act on (no GitHub mutations).

Repairing the finding exposed that the real defect was **tier selection**, in
both directions. `wire_task_idempotency` landed claims on any configured
`pg_pool`, while `wire_execution_spine` lands Runs there only when
`spine_is_migrated` passes — so the container's own comment ("Same backend the
spine just chose") was false whenever a pool was configured but unmigrated:
durable claims beside an in-memory spine make a restart-retry *replay a
receipt whose Run died* — a false reconciliation, work silently lost. The
opposite corner was the audited one: provisioning failure degraded claims to
process-local beside a spine that might be durable, minting a second Run for
the first retried submission after a restart. The repair makes the container's
promise true by construction:

- `runs/wiring.py`: the probe goes public as `spine_is_migrated` (one
  definition — the tiers cannot drift on which pool is durable).
- `tasks/idempotency.py`: claims land on the pool only when the spine's probe
  says the spine lives there; provisioning failure on a spine-ready pool now
  raises `ConfigError` and the process does not start (fail-closed — no
  process-local fallback on a configured healthy PostgreSQL); a pool the spine
  refused gets no claims at all, which follow the spine down to SQLite or
  in-memory, loudly. The deferred import is forced: `runs.wiring` imports
  `tasks.admission`, which imports this module.

**Reconciliation note (issue text vs convention).** The spine's accepted
convention (`spine_is_migrated`, with #122/#132 provenance in its docstring)
is loud-degrade, never startup-crash, for a configured pool the spine itself
cannot make durable — and claims-in-memory beside an ephemeral spine is the
honest tier there, not a cache in front of durability. The one case this
repair still refuses to start for is a spine-ready pool whose claims DDL is
refused: durability asymmetry against a *healthy* database is a
misconfiguration, and the wire says so.
