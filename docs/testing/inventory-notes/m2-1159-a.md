# #1159 — redact credential shapes in security output and approval evidence

Implements #1159 on top of the salvaged diff: one canonical secret policy
(`security/secret_policy.py`) shared by the log redactor, the Sentinel PII
filter, and approval-evidence redaction, plus construction-time redaction of
`Violation.detail` in both Violation classes. +135 tests, all additions, no
removals, across five files:

- `tests/security/test_redact.py` (+45): the Slack `xox*` family
  (xoxa/xoxb/xoxp/xoxr/xoxs, left-boundary and short-tail false-positive
  guards, JSON-precedence); the validated 40-char AWS secret access key
  (canonical shape, pairing with its AKIA ID, and the false-positive controls:
  single-case hex git SHAs, 39/41-char runs, digitless runs, the 20-char AKIA
  ID keeping its identifier label); generic secret assignments (8
  quoting/spacing/case variants with the name preserved and only the value
  redacted, base64-padded bare values, tokenizer/secretary/monkey/author
  non-names, URLs, sub-floor values, more-specific-label precedence inside a
  value, the chained-prefix regression, and the `name=<secret>` adjacency
  label rule); and bare `key` in the JSON field-name alternation (bare,
  prefixed, suffixed, dashed, dotted — with `keynote` and the pre-existing
  `monkey`/`author`/`tokenizer`/`secretary` guards).
- `tests/security/test_secret_policy.py` (new, +59): the canonical classifier
  itself — 23 sensitive field names (segments, camelCase, `pat`, trailing
  digits, strong-family-over-`id`) and 15 that survive (identifier escapes
  `aws_access_key_id`/`key_arn`/`token_id`, ordinary words, empty/blank); the
  AWS secret validator's look-alike rejections; and the assignment-shape spans
  (quoted/bare/double-quoted offsets, non-assignments, and the innermost-
  assignment rule for `x: key=...` / `error: db_password=...` /
  `config: signing_key = "..."` chains).
- `tests/security/sentinel/test_pii_filter_properties.py` (+18): the
  `slack_token`, `aws_secret_key`, and `secret_assignment` labels; the
  detector-order rule (`key=AKIA...` stays typed `aws_key`, named passwords
  stay `password`); false-positive controls (git SHAs, AKIA IDs, ordinary
  words, URLs, `name=<secret>` adjacency typing); and a pin that email +
  payment-card detection is unchanged.
- `tests/capabilities/test_durable_approval.py` (+4): `redact_approval_value`
  covering the key synonyms that previously bypassed (`private_key`,
  `ssh_key`, `signing_key`, bare `key`, camelCase `apiKey`, trailing-digit
  `KEY2`); identifier names surviving; nested mappings/lists/tuples walked
  with list values unclassified; and attacker-controlled key names failing
  toward redaction.
- `tests/security/test_violation_detail_redaction.py` (new, +8):
  `Violation.detail` redacted at construction in BOTH classes
  (`maistro.security._types.Violation` and the frozen
  `maistro.types.security.Violation`), before any AuditLog implementation can
  persist — including the detail carried inside `AuditEntry.violations` —
  with ordinary detail text passing through undestroyed and the frozen
  contract still holding.

Also fixed while validating (not salvageable as-is): the shared
`SECRET_ASSIGNMENT_PATTERN` was superlinear on long unbounded token runs
(AC-36 scaling ratio 25x on `w://x:<a-run>`) and could let an outer
regex-valid-but-non-credential name swallow an inner `name=value` assignment
(`error: db_password=hunter2pass` leaked); the name-token boundary and the
bare-value chain guard fix both (ratio 4.0x). `redact()` now skips an
assignment span that overlaps a more-specific detector's span, so the AC-8
`[REDACTED_AWS_KEY]` label and the documented "specific label wins" contract
hold. Verified +135 = collected (9683) vs recorded (9548); every suite besides
`packages/maistro-core/tests` unchanged.
