Also fixed while validating (not salvageable as-is): the shared

assignment span that overlaps a more-specific detector's span, so the AC-8

hold. Verified +135 = collected (9683) vs recorded (9548); every suite besides

Repair pass (independent acceptance probe against production behavior found
three reachable leaks the first pass's tests missed; +16 tests, no removals):

1. **Assignment values leaked raw when any other redactable span appeared
   later in the same text.** `redact()`'s skip test for assignment spans that
   overlap a more-specific detector's span was `start < end and span[0] < end`
   — not an interval-overlap predicate: any claimed span ending after the
   assignment value starts (e.g. a Slack token later in the line) suppressed
   the assignment, and `my_secret = 'hunter2pass' … xoxb-…` survived with the
   credential intact. Now the standard predicate `span[0] < end and start <
   span[1]` (`test_redact.py::test_assignment_redacted_even_with_an_unrelated_later_span`)
   — and `test_redaction_is_idempotent_across_passes` pins that the first
   pass actually removes everything and a second pass is a fixed point.
2. **camelCase field names bypassed the canonical classifier.**
   `is_secret_key_name` lower-cased the name before the camel-boundary split,
   so `privateKey`, `SigningKey`, `MySecret`, `clientToken`, `userPassword`
   classified as ordinary — and durable approval evidence persisted them
   (`redact_approval_value` is the #329/#1133 evidence seam). The split now
   runs on the original spelling (`test_secret_policy.py` both directions;
   `test_durable_approval.py::test_redact_approval_value_covers_camelcase_synonyms`),
   with camelCase identifiers (`awsAccessKeyId`) keeping the identifier escape.
3. **A PEM body survived the Sentinel PII filter.** The `private_key`
   detector matched only the `-----BEGIN` header, and the base64-decode
   candidate path cannot catch a key body (it decodes to non-UTF-8 bytes), so
   post-call output kept the actual reusable credential with a redacted
   header. A full-block detector (the log redactor's shape) now runs first;
   the header-only form remains the fallback for truncated output
   (`test_pii_filter_properties.py::test_full_pem_block_body_is_redacted`,
   `test_truncated_pem_header_still_detected`).

   Related stability fix: every `SECRET_ASSIGNMENT_PATTERN` value alternative
   now refuses the reserved `[REDACTED…` label namespace. Without that, a
   second pass re-claimed earlier placeholders as assignment values and
   relabeled them (`[REDACTED_AWS_SECRET_KEY]` →
   `[REDACTED_SECRET_ASSIGNMENT]`), breaking idempotence for multi-boundary
   pipelines (`test_redact.py::test_second_pass_keeps_the_specific_label`,
   `test_label_namespace…` covered inside it).
