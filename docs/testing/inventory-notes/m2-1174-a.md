# 1174-dag-run-scope

Twenty-one new collected cases under `packages/hive-conductor/backend/tests`
(all additions, no removals) pinning #1174's scoping of the DAG-Run read
surface and of the run-data readers behind it, across two repair rounds:

Round 1 (+11: 10 node IDs in `test_dag_run_scope.py`, 1 in
`test_eval_judge.py`):

- `test_dag_run_scope.py` (9 tests, one parametrized over three paths): list
  shows in-Workspace runs and hides out-of-Workspace ones (with the universal
  invariant: every listed row's Workspace is the caller's own); detail serves
  in-Workspace runs while out-of-Workspace ids get the exact non-existence
  answer a missing id gets (indistinguishable 404); SSE refuses an
  out-of-scope run before any stream exists while in scope the handler opens
  a `text/event-stream` that replays buffered events (asserted at handler
  level — starlette's TestClient buffers infinite streams); unauthenticated
  reads are 401 before any existence signal; a projection row written without
  Workspace scope is visible to no one (fail-closed; #1036's migration owns
  re-scoping).
- `test_eval_judge.py`:
  `test_trigger_score_out_of_scope_run_is_not_scored` — the eval-judge
  trigger reads the projection through the same scoped inspection door, so a
  run outside the caller's Workspace universe is never scored and answers
  with the run's usual 404.

Round 2 (+10, repair of the verify findings — the eval-judge read side was
still unscoped, and two acceptances had no test):

- `test_dag_run_scope.py`, eval-judge read side over the same door (4 tests):
  a verdict recorded for an out-of-scope run is neither served nor hinted at
  (byte-identical non-existence answer, secret rationale absent from the
  body); an in-scope verdict is served; "no verdict for run_id" is reachable
  only for a run the caller may already inspect; the verdict list hides
  out-of-scope rows. The unauthenticated-401 parametrization grew from three
  to five paths (`/v1/eval-judge`, `/v1/eval-judge/{run_id}`).
- `test_dag_run_scope.py`, canonical → projection scope mapping (3 tests):
  `canonical_dag_runner._project` copies run_id/workspace_id/project_id
  verbatim off the canonical Run record; the run route's
  `_record_run_projection` opens a projection row born with that canonical
  scope (canonical_run_id == run_id, no second identity) which inspection
  then enforces two-principal; the chat workflow tool opens the row before
  executing with the scope `resolve_execution_scope` resolves.
- `test_dag_run_scope.py`, revocation (1 test):
  `test_revoking_workspace_membership_revokes_run_visibility` — a
  two-principal E2E where the run is listed/readable while the membership
  grant stands and every door (list, detail, SSE) answers the exact
  non-existence response the moment the owner revokes it.
- `test_eval_judge.py` (0 net): the three verdict-endpoint tests that
  persisted verdicts for runs absent from the projection were re-seeded to
  create the run inside a caller-owned Workspace first — they had been
  pinning exactly the cross-Workspace read the repair closes; plus an
  autouse verdict-wipe fixture for isolation.
