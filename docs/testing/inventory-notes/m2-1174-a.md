# 1174-dag-run-scope

Eleven new collected cases under `packages/hive-conductor/backend/tests`
(10 in the new `test_dag_run_scope.py` + 1 in `test_eval_judge.py`), all
additions, no removals. They pin #1174's scoping of the DAG-Run read surface
(`/v1/dag-runs` list, detail, SSE) and of the run-data reader behind the
eval-judge trigger:

- `test_dag_run_scope.py` (9 tests, one parametrized over three paths → 10
  node IDs): list shows in-Workspace runs and hides out-of-Workspace ones
  (with the universal invariant: every listed row's Workspace is the
  caller's own); detail serves in-Workspace runs while out-of-Workspace ids
  get the exact non-existence answer a missing id gets (indistinguishable
  404); SSE refuses an out-of-scope run before any stream exists while in
  scope the handler opens a `text/event-stream` that replays buffered
  events (asserted at handler level — starlette's TestClient buffers
  infinite streams); unauthenticated reads are 401 before any existence
  signal (3 paths); a projection row written without Workspace scope is
  visible to no one (fail-closed; #1036's migration owns re-scoping).
- `test_eval_judge.py` (+1): `test_trigger_score_out_of_scope_run_is_not_scored`
  — the eval-judge trigger reads the projection through the same scoped
  inspection door, so a run outside the caller's Workspace universe is never
  scored and answers with the run's usual 404.
