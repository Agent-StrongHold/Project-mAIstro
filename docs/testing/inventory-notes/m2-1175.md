# m2-1175 — Workspace-scoped, referentially complete Run retention

**+33 `packages/maistro-core/tests`** — twenty-six collected node IDs in the
new `tests/runs/test_retention_scope_conformance.py` (eight tests
parametrized over the memory/sqlite/postgres spine legs + two scope-value
tests) and seven new unparametrized cases in `tests/runs/test_retention_policy.py`.
`test_retention_conformance.py` and `test_chat_retention_sweep.py` were
rewritten for the new purge signature but changed no node IDs.

- `test_retention_scope_conformance.py` (26): two Workspaces with expired
  terminal Runs plus continuation, Event, and schedule-occurrence references
  prove one Workspace's purge deletes only its own Run and spine (with
  dependent counts), takes the Graph continuation with its Run while leaving
  the other Workspace's traversal state alone, preserves the append-only
  Event log (counting the retained references the purge leaves behind — zero
  on the memory leg, which owns no Event log, is the truthful boundary
  report), releases only the purged Run's own occurrence claim (the other
  Workspace's claim still refuses a duplicate), and leaves zero orphaned
  canonical evidence. Also: a global sweep is an explicitly attributed act
  (`GlobalRetentionScope` names its principal) and touches both Workspaces;
  an empty Workspace id or blank principal is refused at construction; a
  batch-limited sweep reports `backlog_remaining` (True, then False when
  drained); concurrent sweeps of different scopes partition the work and
  never cross.
- `test_retention_policy.py` (+7): a sweeper with no scope deletes nothing
  and records the refusal instead of sweeping store-wide; `sweep_now`
  propagates that refusal; a per-sweep scope overrides the construction
  scope; a global scope reaches the store intact and reports mode
  `global`/`workspace_id` `None`; the `PurgeOutcome` names the authorized
  Workspace; purged Runs are counted by bounded mode label (never a
  Workspace id, per the #818 label bound); a failed sweep counts nothing and
  clears `last_outcome`.

The purge API itself changed shape: `purge_expired_runs(scope, *, now,
limit)` takes a required `RetentionScope` (a `WorkspaceRetentionScope`, or a
`GlobalRetentionScope` carrying an `authorized_by` grant), and returns a
`PurgeOutcome` — scope, per-class dependent counts (runs / node_runs /
attempts / continuations / event references retained / schedule claims
released), and `backlog_remaining` — which `RunRetentionSweeper.last_outcome`
exposes and `maistro_retention_purged_total{mode}` aggregates. The SQLite and
PostgreSQL purges push the Workspace predicate into the candidate SELECT and
handle dependent evidence in the purge transaction: `graph_continuations`
(migration 021, no FK) is deleted with its Run; `canonical_event_log`
(migration 030) is kept and counted.

Verified +33 = collected (26 + 7) against the prior recorded inventory; the
runs/retention suites pass on the memory and sqlite legs with the postgres
legs skipping cleanly where `MAISTRO_TEST_PG_DSN` is unset, unchanged from
the pre-existing conformance fixtures.
