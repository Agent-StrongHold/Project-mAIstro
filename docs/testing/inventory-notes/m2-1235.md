# #1235 develop-head gate reconciliation: trusted-base self-checks and gitleaks specimens

No node-count change. Nine existing tests were modified; no tests were added,
removed, or renamed, so `SUITE-INVENTORY.md` collected node IDs are unchanged.

## What was red and why

At develop head `1980f9fa` three gates failed (`test`, `Coverage gate
(publish-set floor + diff coverage)`, `SAST (bandit + semgrep + gitleaks)`).
Two independent roots:

1. **The seven shipped-state gate self-checks could not resolve a trusted
   base on a push to `develop`.** `tests/test_check_execution_lifecycles.py`,
   `tests/test_check_model_egress.py`, `tests/test_check_public_routes.py`
   and `tests/test_mutation_baseline.py` (4) assert gate `main()` results
   against the real repository. The autouse `_default_ac_state_ratchet_event`
   fixture in `tests/conftest.py` deliberately strips GitHub event metadata
   (temp-repository hermeticity), so the ratchet resolver fell back to
   `origin/develop` — which IS HEAD on a develop push, with a clean worktree
   exactly the self-referential state #534 refuses. Every self-check exited
   "cannot compare" (exit 1/2) instead of "compared and passed"; the two
   gate-expects-failure tests passed only vacuously. The coverage gate's red
   is the same seven tests: its 87% publish-set floor passed (TOTAL 92%) and
   the failure is the `tests/` producer run inside the combine step.

2. **Gitleaks flagged five reviewed false positives reachable from origin
   refs.** Four are the invented padding-like sample value quoted by the
   shared secret-shape documentation (`abc=def12345`, introduced to origin by
   the #1159 branch); one is the PII-filter fixture's PEM-template f-string
   whose body is the `{body}` placeholder — no key material on the line.
   Because the develop push arm scans full history across all refs, a
   specimen on any branch reds the gate.

## The repair (doctrine-following, not gate-weakening)

- `ci.yml` `test` job and `quality.yml` `coverage-gate` job now name the
  event's own base in `RATCHET_BASE_REV`, exactly as `vulture-ratchet.yml`
  already does — the resolver's own documented remedy ("Name the event's own
  base explicitly in RATCHET_BASE_REV").
- `tests/conftest.py` captures the ambient value at import time, adds
  `RATCHET_BASE_REV` to the fields the hermeticity fixture strips, and
  exposes `real_repository_ratchet_base`, the opt-in channel the fixture
  docstring always promised ("a test wanting GitHub event semantics sets the
  relevant variables in its own body"). The nine gate self-check tests opt
  in; every temp-repository test keeps the no-base default (251 ratchet/
  temp-repo tests verified green with the ambient value set).
- `tests/test_check_model_egress.py`'s gate fixture inserts `scripts/` on
  `sys.path` itself instead of inheriting an alphabetically earlier module's
  insertion — isolated runs of the file no longer error before the assertion.
- `.gitleaks.toml` records the two reviewed specimen identities as
  content-scoped allowlist entries (line- and commit-independent, scoped to
  the one rule family each). Negative controls: a full PEM block and a
  well-formed GitHub PAT remain detected with the entries present; removing
  the entries re-reports all five findings.

## Local-run semantics (unchanged, documented)

A clean local checkout of `develop` still refuses unnamed-base ratchet runs —
that is #534 working as designed. Local loops are unaffected (dirty worktree
or a base behind HEAD both compare normally); a developer who wants the
shipped-state self-checks judged on a clean develop checkout names the base
explicitly, as CI now does.
