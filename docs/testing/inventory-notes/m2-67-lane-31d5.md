# m2-67-lane-31d5 — issue #67: CGNAT class + the sync seam

Two gaps in the outbound SSRF policy (#67), each closed with tests at the
layer that owns it. All 13 node IDs are in `packages/maistro-core/tests`:

- `tests/security/test_ssrf.py` (+5 node IDs): the RFC 6598 shared range
  (`100.64.0.0/10`, carrier-grade NAT) is now refused — three parametrized
  cases across the range — and two boundary cases prove the block stops at the
  /10 mask (`100.63.255.255` and `100.128.0.1` stay reachable). The range had
  to be listed explicitly: CPython's `is_private` is derived from the IANA
  special-purpose registry's *private* fragment, and the registry files
  100.64.0.0/10 under *shared address space*, so every predicate is False for
  `100.64.0.1` on every Python this repo supports (measured on 3.12.12).
- `tests/security/test_outbound_policy.py` (+8 node IDs): the new synchronous
  seam (`SyncGuardedTransport` / `maistro.http.sync_client`) is held to the
  same properties the async seam is — private target refused before the
  transport, CGNAT refused, public target reached, redirect-into-private
  refused at the hop, an allowance honoured without widening,
  wrapping idempotent across transports and proxy mounts, `MockTransport`
  left alone — plus one test that the approvals CLI client (the module the
  async-only pool could not reach) is guarded and registers exactly its
  operator-configured origin.

No suite lost or moved counts; the whole delta is additive in maistro-core.
