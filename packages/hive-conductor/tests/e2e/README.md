| `rsi-polling-resilience.spec.ts` | **Yes** | Same job, same config. Drives the RSI page through every failure shape its two poll loops must survive (#359): unreachable (transport), 5xx, and 401/403 render as three DISTINCT states (and a no-answer poll renders "status unknown", never a fake "not installed"), an intermittent outage keeps last known data on screen and clears its banner on recovery with zero uncaught page errors, a prolonged outage backs off exponentially (interval·2^failures at 75% pinned jitter, exact gaps under `page.clock` on an ISOLATED context — Playwright's clock registers context-level init scripts, so sharing it would pause every later navigation) until the 60s cap floors the cadence (~7 polls per five virtual minutes, not ~60), a success resets the failure ladder to fresh (7.5s, not 15s) and re-arms the base interval, the loop pauses while the tab is hidden or the browser is offline and re-kicks on visibilitychange/online, an unmount rejects the in-flight patch-feed fetch as AbortError (a request held by a pending route handler emits no Node-side `requestfailed`) and stops both loops, and a slow response never overlaps the next poll. |

The three excluded files are deliberate, not an oversight (see #286): they need an unvendored
heavy dependency and/or live third-party credentials that don't belong in a public CI run. Run
them locally per their own docstrings (`make test-agent`, `make test-vision`, or directly with
`GOOGLE_API_KEY` set) — see `../PM-WALKTHROUGH.md`.
